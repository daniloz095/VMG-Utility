# Установка M Vitals+ на машину (MGU / iDrive 7) и проверка

Инструкция рассчитана на root-доступ по SSH к головной части (HU), который у вас уже есть.

---

## 0. Что нужно заранее

| Компонент | Зачем | Где взять |
|---|---|---|
| Node.js 8.x на ПК | SDK и приложения MGU работают на Node 8; newer версии ломают сборку | https://nodejs.org (nvm: `nvm install 8`) |
| Python 3 | скрипт сборки | системный |
| oap-sdk | код BMW, без него не собрать `.mgu` | извлечь с HU — см. `docs/OAP-SDK.md`, шаг 1–2 ниже |
| SSH-ключ для HU | деплой | свой ключ, например `~/.ssh/id_mgu` |

IP головной части: обычно виден в сети как устройство BMW (например, `192.168.x.x`).
Проверка связи: `ssh root@<IP>` (зажигание включено или машина «проснулась»).

---

## 1. Извлечь oap-sdk с HU (однократно)

```sh
# донор — прошивочное приложение x_call (SDK 24.10.x, полный API)
scp root@<IP>:'/usr/lib/oap-mainapp/preinstalled_apps/x_call@*.tgz' .
mkdir x_call && tar xzf x_call@*.tgz -C x_call

# если x_call нет — посмотреть, что есть:
ssh root@<IP> 'ls /usr/lib/oap-mainapp/preinstalled_apps/'

# вариант посвежее (SDK 27.x, нам тоже подходит):
# scp root@<IP>:/var/opt/public/oap/oap_12204/source/javascript/app.js ./app.js

# извлечение (пишет в ./oap-sdk/)
node kit/tools/extract_sdk.js x_call/javascript/app.js
```

ВАЖНО: папку `oap-sdk/` никогда не коммитить и не публиковать — это код BMW.
Готовые `.mgu`-пакеты тоже содержат его: храните только для своей машины.

---

## 2. Собрать приложение

```sh
python3 kit/tools/build.py m_vitals_plus
# результат: dist/m_vitals_plus@0.1.0.mgu
```

Если сборщик требует npm-зависимости — ставьте их под Node 8 (`nvm use 8`).

### Быстрая проверка без машины (эмулятор)

```sh
node kit/tools/emu.js m_vitals_plus
# открыть http://localhost:8077 — UI работает с мок-данными
```

(Эмулятор опционален: визуальные превью вкладок уже лежат в `apps/m_vitals_plus/sim/*.png`,
регенерация: `node kit/tools/simulate.js m_vitals_plus <вкладка>`.)

## 3. Установить на HU

Два способа. Первый — через MGU Store, если он стоит на машине (самый простой).
Второй — вручную по SSH (работает всегда).

### Способ A. MGU Store

1. Положите `dist/m_vitals_plus@0.1.0.mgu` на флешку (FAT32) или раздайте по Wi-Fi так,
   чтобы MGU Store мог его подхватить (Store → «Install from file» / локальная папка apps).
2. В Store выберите пакет → Install. Приложение появится в меню OAP («M Vitals+»).

### Способ B. Ручная установка по SSH

```sh
# 1. распаковать .mgu (это tar.gz) во временную папку на ПК
mkdir /tmp/mvp && tar xzf dist/m_vitals_plus@0.1.0.mgu -C /tmp/mvp

# 2. положить на HU в папку приложений
scp -r /tmp/mvp root@<IP>:/var/opt/private/oap/m_vitals_plus

# если на HU нет прав на запись в /var/opt/private/oap — уточните путь:
ssh root@<IP> 'ls /var/opt/private/oap/ ; ls /usr/lib/oap-mainapp/preinstalled_apps/'

# 3. дать права владельцу OAP и перезапустить онлайн-агент
ssh root@<IP> 'chmod -R a+rX /var/opt/private/oap/m_vitals_plus; killall oap-mainapp || true'
```

oap-mainapp перезапускается автоматически (~5–10 секунд). После этого в списке
приложений (Eject/Menu → Apps) появится «M Vitals+».

Удаление: `ssh root@<IP> 'rm -rf /var/opt/private/oap/m_vitals_plus; killall oap-mainapp'`.

Обновление: повторить шаги 2–3 поверх (папка заменяется целиком).

## 4. Проверка на машине (чек-лист первого запуска)

1. **Зажигание ON, двигатель можно не запускать.** Открыть приложение.
2. Демо-режим: в SETTINGS → `demo` поставить `off` (иначе цифры симулируются).
3. Пройтись по вкладкам MAIN | POWER | HPFP | IGNITION | FUEL/COOL | ELECTRIC | XDRIVE | LAP | MORE | SETTINGS:
   - MAIN: наддув, температуры, давление масла, λ должны появиться в течение ~10–20 с
     после запуска двигателя (часть DID отвечает только при работающем DME);
   - плитки с `--` = DID не откликнул — это нормально для первых прогонов, см. п.4;
   - KNOCK/MISFIRE счётчики: должны расти ТОЛЬКО когда наддув > 0.5 бар.
4. **Калибровка DID.** Откройте логи HU:
   ```sh
   ssh root@<IP> 'logread | grep -i m_vitals | tail -50'
   ```
   В логе видно, какие кандидаты DID перебираются и какие значения пришли raw.
   Если метрика показывает неправдоподобно (например, EGT = 25°C на горячую или
   давление масла = 300 бар) — пришлите мне строки лога, поправим масштабирование
   и список кандидатов в `app.json → config.dids`.
5. **LAP:** на парковке проверить тогл START→STOP при скорости 0; полноценный замер
   — только на закрытой дороге.
6. **MORE → EXHAUST FLAP:** первый тест стоя, двигатель прогрет, скорость 0.
   Кнопка OPEN/CLOSE должна двигать заслонку (слышен сервопривод, положение
   меняется на экране). Интерлоки: команда блокируется на ходу.

### Безопасность

- UDS-запись (`writeData`/`releaseIOControl`) используется только для заслонки и только
  через штатный диагностический gateway SOME/IP; ничего не шьём в DME.
- Если хотите вообще запретить записи — в SETTINGS поставьте `flapWrite=off`
  (экран заслонки останется read-only).
- Все counters/графики — чистое чтение сигналов, на гарантию и работу авто не влияют.

## 5. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| Приложения нет в меню | Не тот путь установки → `ls /var/opt/private/oap/`; перезапуск `killall oap-mainapp` |
| Черный экран при открытии | Версия Node на HU ≠ версии SDK: пересоберите извлечённым SDK именно этой машины |
| Все плитки `--` | Двигатель заглушен (DME не отвечает на readData) или ECU id не совпадает — пришлите logread |
| Наддув скачет/не тот | FES-резерв имеет другую калибровку — зафиксируем коэффициент по вашему логу |
| Температура масла `--` | COM-сигнал приборки отсутствует на вашей комплектации — переключим на DID DME |

Приложите к сообщению: вывод `logread | grep m_vitals`, скриншот экрана и версию
прошивки (SETTINGS → About / `ssh root@<IP> 'cat /etc/version'`).
